# Phase 2 실제 진동 데이터 가이드

## 1. 결론

Phase 2에서 osESD에 직접 넣을 데이터는 **한 측정 채널의 시간에 따른 트렌드 값**이다.

```text
(SYS1_ID, 회사/사이트 범위, POINT_ID, MEASUREMENT_ID, AGGR_TIME_CD, 단위)
를 고정한 뒤
TS 오름차순의 VAL 시계열 1개를 만든다.
```

`TB_WAVEFORM_LOG_*`.`C_DATA`는 한 시점에 고속 수집한 원시 파형이다. 장기 온라인 이상 탐지의 기본 입력이 아니라, 트렌드에서 검출된 이상 시점의 파형·FFT 원인을 확인하는 보조 데이터로 사용한다.

가장 작은 유효한 Phase 2 범위는 다음과 같다.

1. 설비 1대
2. 의미와 단위가 같은 채널 1~3개를 각각 독립 시계열로 처리
3. 집계 코드 하나만 사용
4. 고정 osESD 파라미터로 1차 검출
5. 알람 및 정비 이력과 비교

여러 채널을 한 시계열로 합치거나, 트렌드와 파형 샘플을 이어 붙이지 않는다.

- SKF 대표 속도 채널: 약 1분
- SYS01 대표 속도 채널: 약 3분 30초이며 간격 변동이 큼

## 4. 데이터 종류

### 4.1 트렌드 데이터: Phase 2 주 입력

시스템별 테이블은 다음과 같다.

| `SYS1_ID` | 트렌드 테이블 | 파형 테이블 |
|---|---|---|
| `99` | `TB_TREND_LOG_SKF` | `TB_WAVEFORM_LOG_SKF` |
| `01` | `TB_TREND_LOG_SYS01` | `TB_WAVEFORM_LOG_SYS01` |
| `04` | `TB_TREND_LOG_SYS04` | `TB_WAVEFORM_LOG_SYS04` |

트렌드의 핵심 컬럼은 다음과 같다.

| 컬럼 | 의미 | Phase 2 처리 |
|---|---|---|
| `SYS1_ID` | 원천 시스템 및 물리 테이블 구분 | 반드시 고정 |
| `COMPANY_ID` | 회사/사이트 범위 | 가능한 경우 반드시 고정 |
| `API_PORT` | SKF 범위 구분 | SKF에서는 가능한 경우 반드시 고정 |
| `POINT_ID` | 측정 포인트 | 반드시 고정 |
| `MEASUREMENT_ID` | 측정 채널 | 반드시 고정 |
| `AGGR_TIME_CD` | `RAW`, `2M`, `10M`, `1H`, `1D` 등의 집계 수준 | 하나만 고정 |
| `TS` | 측정 시각 문자열 | 오름차순 정렬 후 숫자 시간으로 변환 |
| `VAL` | 실제 단변량 측정값 | osESD의 `value` |
| `VAL_TYPE` | 값 유형 플래그 | 의미를 실데이터에서 확인 후 필터 결정 |

채널 이름과 단위는 `TB_EQUIP_SETPOINT`에서 얻는다.

```text
TB_EQUIP_SETPOINT.SYS1_ID       = trend.SYS1_ID
TB_EQUIP_SETPOINT.LOCAL_ID      = trend.POINT_ID
TB_EQUIP_SETPOINT.MEASUREMENT_ID = trend.MEASUREMENT_ID
```

단위 예시는 `mm/s`, `g`, `µm`이지만, 이름만 보고 RMS/Peak/Peak-to-Peak을 추정하면 안 된다. `MEASUREMENT_NM`, `MEASUREMENT_UNIT`, 원천 시스템 정의를 함께 확인해야 한다.

### 4.2 파형 데이터: 이상 시점의 보조 근거

`TB_WAVEFORM_LOG_*`의 주요 컬럼은 다음과 같다.

| 컬럼 | 의미 |
|---|---|
| `UTC_TIME_STAMP` | 파형 수집 시각 |
| `SAMPLING_PERIOD` | 샘플 간격(초) |
| `NO_OF_DATA` | 파형 샘플 수 |
| `C_DATA` | 시간 영역 샘플의 JSON 배열 |
| `UNIT`, `UNIT_NAME` | 파형 진폭 단위 |
| `RPM` | 해당 시점 회전수 |
| `FMAX` | 분석 대역 상한(Hz) |

현재 iFacts 코드에서 세 원천 시스템의 `C_DATA`는 시간 영역 데이터로 취급한다. 평균 제거 후 `numpy.fft.rfft()`를 수행하고, 샘플링 주기가 없을 때만 `1 / (2 × FMAX)`를 fallback으로 사용한다. FFT 결과는 `FMAX` 미만 대역만 유지한다.

따라서 다음을 구분해야 한다.

- 트렌드 `VAL`: 시간에 따른 상태값 한 점
- 파형 `C_DATA`: 한 수집 시점 안의 고속 샘플 배열
- FFT amplitude: 파형에서 계산한 주파수별 진폭

이 세 값은 시간축과 물리적 의미가 다르다.

### 4.3 설비·센서 메타데이터

`TB_TREE_ALL`은 설비 계층이고 `LOCAL_ID`는 문자열이다. 트렌드의 `POINT_ID`와 조인할 때 형 변환이 필요하다. 또한 iFacts 코드에는 신규 트리 모델과 레거시 setpoint 경로가 함께 존재한다. 다음 ID를 같은 값이라고 가정하지 않는다.

- 설비 노드 `LOCAL_ID`
- 측정 포인트 `POINT_ID`
- 채널 `MEASUREMENT_ID`

동일한 `MEASUREMENT_ID`가 다른 포인트에서 재사용될 수 있으므로 최소 키는 `SYS1_ID + POINT_ID + MEASUREMENT_ID`이다. SKF 및 다중 회사 환경에서는 `API_PORT`, `COMPANY_ID`도 범위 키에 포함한다.

## 5. osESD 입력 계약

osESD는 단변량 시계열을 입력받는다. 실제 진동 데이터는 채널별로 아래 형태로 정규화한다.

| 컬럼 | 필수 | 설명 |
|---|---|---|
| `timestamps` | 예 | 엄격하게 증가하는 숫자 시간. Unix 초 또는 첫 관측 이후 경과 초 |
| `value` | 예 | 유한한 실수형 트렌드 값 |
| `anomaly` | 평가 시 | 정상 `0`, 이상 `1`의 검증 라벨 |
| `source_ts` | 보존 권장 | 원본 `TS` 문자열 |
| 식별자·단위 컬럼 | 보존 권장 | 결과 추적용이며 모델 입력에는 섞지 않음 |

예시:

```csv
timestamps,source_ts,value,anomaly,sys1_id,point_id,measurement_id,aggr_time_cd,unit
0,2026-01-01 00:00:00,0.221,0,99,15,17,2M,mm/s
120,2026-01-01 00:02:00,0.225,0,99,15,17,2M,mm/s
240,2026-01-01 00:04:00,0.811,1,99,15,17,2M,mm/s
```

DB의 시각 문자열을 그대로 `timestamps`에 넣으면 안 된다. 현재 osESD 내부 변환은 시간을 `float`로 바꾸므로 ISO 문자열은 실패한다. 실제 간격이 불규칙할 수 있으므로 단순 행 번호보다 경과 초를 권장한다.

## 6. 추출 및 품질 검사

### 6.1 추출 원칙

한 파일 또는 한 DataFrame에는 다음 키가 모두 동일한 행만 둔다.

```text
SYS1_ID
COMPANY_ID
API_PORT(해당 시)
POINT_ID
MEASUREMENT_ID
AGGR_TIME_CD
측정 단위와 측정 의미
```

SKF 예시 SQL은 다음과 같다. 실제 실행 시 범위 값을 명시하고 기간 조건을 반드시 둔다.

```sql
SELECT
    t.SYS1_ID,
    t.COMPANY_ID,
    t.API_PORT,
    t.POINT_ID,
    t.MEASUREMENT_ID,
    t.AGGR_TIME_CD,
    t.TS,
    t.VAL,
    t.VAL_TYPE,
    s.MEASUREMENT_NM,
    s.MEASUREMENT_UNIT
FROM TB_TREND_LOG_SKF t
LEFT JOIN TB_EQUIP_SETPOINT s
  ON s.SYS1_ID = t.SYS1_ID
 AND s.LOCAL_ID = t.POINT_ID
 AND s.MEASUREMENT_ID = t.MEASUREMENT_ID
WHERE t.SYS1_ID = :sys1_id
  AND t.COMPANY_ID = :company_id
  AND t.API_PORT = :api_port
  AND t.POINT_ID = :point_id
  AND t.MEASUREMENT_ID = :measurement_id
  AND t.AGGR_TIME_CD = :aggr_time_cd
  AND t.TS >= :from_ts
  AND t.TS < :to_ts
ORDER BY t.TS ASC;
```

`SYS01`, `SYS04`는 대응 테이블을 사용하고 실제 컬럼 존재 여부에 맞춰 `API_PORT` 조건을 제외한다. 애플리케이션 API를 사용할 경우 `GET /api/v1/equipment/{local_id}/trend`가 `ts`, `val`, 식별자, 집계 코드, 채널명, 단위를 반환하며 한 요청의 최대 `size`는 10,000이다.

### 6.2 모델 실행 전 필수 검사

1. `TS`를 파싱하고 오름차순으로 정렬한다.
2. 동일 전체 키와 동일 `TS`의 중복을 확인한다. 임의 평균 전에 중복 발생 원인을 확인한다.
3. `VAL`의 null, NaN, infinity, 비숫자 값을 분리해 집계한다.
4. 시간은 엄격히 증가해야 한다. 동일 timestamp는 osESD 변화율 계산의 0 나눗셈 위험이 있다.
5. 실제 시간 간격의 중앙값, 상위 분위수, 긴 공백을 기록한다.
6. 집계 코드와 단위가 중간에 바뀌지 않았는지 검사한다.
7. 센서 교체, 정지 구간, 통신 단절, 보정 변경을 별도 플래그로 보존한다.
8. 첫 `size`개는 detector 초기화 구간이므로 정상 기준 구간인지 확인한다.

결측 시점을 0으로 채우지 않는다. 0은 실제 정지 또는 센서값일 수 있다. 짧은 결측을 보간할지, 구간을 분리할지는 결측 원인이 확인된 뒤 결정한다.

## 7. 집계 수준 선택

`RAW`, `2M`, `10M`, `1H`, `1D`를 한 시계열에서 혼합하면 안 된다.

- `RAW`: 현재 세 시스템 모두 실제 데이터가 없다.
- `2M`: 세 시스템에 공통으로 존재하지만 실제 주기는 약 1초~10분 이상으로 채널별 차이가 크다.
- `10M`: SKF와 SYS01에만 존재한다.
- `1H`, `1D`: 짧은 이상이 집계로 사라질 수 있어 초기 고장 탐지에는 주의한다.

“2M”이 평균, 최대, 마지막 값 중 무엇을 뜻하는지는 DB 행만으로 확정되지 않는다. 다만 실측상 고정된 2분 간격이 아니라는 점은 확인됐다. Phase 2에서는 집계 코드보다 실제 간격, `VAL_TYPE`, 채널 의미를 함께 고정한다.

## 8. 라벨과 평가

운영 진동 트렌드에는 일반적으로 osESD 평가용 `anomaly` 정답 컬럼이 없다. 알람 임계값 초과는 참고 라벨이지 곧바로 고장 정답은 아니다.

라벨 근거의 우선순위는 다음처럼 분리하는 것이 좋다.

1. 정비로 확인된 결함 및 정비 시각
2. 전문가가 검토한 진단 결과
3. 장비 알람 이벤트
4. 임계값 초과만으로 생성한 약한 라벨

알람은 한 시점이 아니라 사건 구간일 수 있으므로 검출 인덱스의 완전 일치보다 허용 시간창 내 검출 여부를 함께 평가한다. Precision, Recall, F1 외에도 다음 운영 지표가 필요하다.

- 장비·채널·일 단위 오탐 수
- 확인된 사건의 사전 탐지 시간
- 정지·기동 구간의 오탐률
- 데이터 단절 직후의 오탐률

라벨이 없으면 `osESD(..., labeled=False)`로 고정 파라미터 검출은 가능하다. `auto_osESD(..., labeled=False)`는 초기 구간에 합성 이상을 주입해 파라미터를 고르므로, 실제 고장 정답으로 튜닝하는 방식이 아니다. Phase 2 첫 실험은 해석이 쉬운 고정 파라미터 osESD를 먼저 권장한다.

## 9. 권장 Phase 2 실행 순서

1. 대상 설비와 채널을 확정한다.
2. 실제 간격과 연속 구간을 확인한 뒤 5,000~20,000개 트렌드를 채널별로 추출한다.
3. 시간, 중복, 결측, 단위, 데이터 간격 보고서를 만든다.
4. 정상으로 확인된 초기 구간이 최소 `size`보다 충분히 긴지 확인한다.
5. 현재 기본값 또는 작은 파라미터 조합으로 고정 osESD를 실행한다.
6. 검출 시점을 알람·정비 이력과 나란히 표시한다.
7. 대표 true positive, false positive, false negative 시점에만 파형을 연결해 FFT와 RPM을 확인한다.
8. 이 결과가 유효할 때만 다채널 결합이나 자동 튜닝으로 확장한다.

Phase 2에서 바로 다채널 모델, 실시간 서비스, 파형 특징 결합까지 만들 필요는 없다. 먼저 “한 채널 트렌드에서 유용한 이상 시점을 안정적으로 찾는가”를 검증한다.

## 10. Phase 2 대상 선택 질문

작업을 시작하려면 아래 네 가지가 필요하다.

1. 첫 대상 회사/사이트와 설비는 무엇인가?
2. 우선 볼 채널은 속도 RMS, 가속도 RMS/Peak, 변위 중 무엇인가?
3. 분석 기간과 사용할 집계 코드의 실제 의미는 무엇인가?
4. 정답은 정비 이력, 전문가 판정, 알람 중 무엇으로 평가할 것인가?

DB 접근과 데이터 구조는 확인됐다. 대상을 정하면 아래 컬럼을 가진 채널별 데이터셋을 바로 추출할 수 있다.

```text
SYS1_ID, COMPANY_ID, API_PORT, POINT_ID, MEASUREMENT_ID,
AGGR_TIME_CD, TS, VAL, VAL_TYPE, MEASUREMENT_NM, MEASUREMENT_UNIT
```

파형은 1차 데이터셋 전체에 포함하지 않아도 된다. 이상 후보 시점별로 `UTC_TIME_STAMP`, `SAMPLING_PERIOD`, `NO_OF_DATA`, `C_DATA`, `UNIT_NAME`, `RPM`, `FMAX`를 별도 연결하면 된다.

## 11. 질문과 답변

아래 답변에서 **사실**은 운영 DB와 현재 코드에서 확인한 내용이고, **의견**은 Phase 2 실험 설계에 대한 제안이다. 파일럿 범위는 `SYS1_ID=99`, `COMPANY_ID=3`, `API_PORT=8082`이고 첫 대상 후보는 `R-3 POLYM PUMP > MOTOR > MTR_H_DE_VEL`이다.

### 11.1 설비와 센서

#### Q1. 대상 설비의 종류와 측정 위치는 무엇이며, 설비·센서·축은 몇 개인가?

**사실**

- 파일럿 사이트 범위에는 train 설비가 8대 있다.
  - `R-3 POLYM PUMP` 4대
  - `R-101 AGT` 4대
- 구성 요소는 `MOTOR`, `GEARBOX`로 표현되어 있다.
- 트리에는 mapped point 16개, sensor 노드 84개가 있다.
- setpoint는 86행이며 이 중 일반 진동 채널은 84개, `test/Other Peak` 2개다.
- 일반 채널은 측정 위치 28개에 각각 VEL, ACC, ENV3가 붙은 구조다.
  - VEL 28개
  - ACC 28개
  - ENV3 28개
- 채널명에는 `MTR_H_DE`, `MTR_H_NDE`, `GBX_H_IN`, `GBX_H_OUT`, `GBX_R0_OUT`이 있다.
- `H`는 horizontal로 해석할 수 있지만 DB에 별도 X/Y/Z 축 컬럼은 없다. `R0`도 명시적인 X/Y/Z 정의가 없다.

**의견**

첫 실험은 8대를 한꺼번에 합치지 말고 `R-3 POLYM PUMP` 한 대의 `MOTOR H DE` 위치에서 시작하는 것이 좋다. 이후 같은 위치의 ACC와 ENV3, 같은 설비의 gearbox 채널, 같은 형식의 다른 3대 순으로 확장한다. 축 정보가 명시적이지 않으므로 `H`, `R0`를 임의로 X/Y/Z로 변환하지 않는다.

#### Q2. 센서 종류, 단위, 샘플링 주파수와 원신호/요약값 구분은 무엇인가?

**사실**

파일럿 범위의 저장 채널은 다음 세 종류다.

| 채널 | 단위 | DB의 값 |
|---|---|---|
| VEL | `mm/s rms` | 일정 주기로 저장된 요약값 |
| ACC | `g rms` | 일정 주기로 저장된 요약값 |
| ENV3 | `gE PtP` | 일정 주기로 저장된 envelope 요약값 |

별도 waveform 테이블의 `C_DATA`는 원신호다. 파일럿의 실제 VEL 파형은 4,096개 샘플, FMAX 1,000 Hz이며 `SAMPLING_PERIOD`는 비어 있다. 현재 코드는 이 경우 Nyquist 가정으로 2,000 Hz sampling rate와 약 2.048초 길이를 추정하지만, 이는 계측기에 기록된 값이 아니라 fallback이다.

**의견**

osESD에는 약 1분 간격의 VEL/ACC/ENV3 요약값을 각각 넣는다. 고속 `C_DATA`를 직접 이어 붙여 osESD에 넣지 않는다. 파형에서는 RMS, peak, crest factor, kurtosis, FFT 대역 에너지 같은 특징을 계산해 별도 저주기 시계열로 만들 수 있지만, Phase 2 첫 단계에는 포함하지 않는 편이 결과 해석이 쉽다.

#### Q3. 연속 수집인가, 일정 간격 스냅샷인가?

**사실**

- 파일럿 VEL 트렌드 최근 5,000건의 간격은 중앙 61초, p95 63초, 범위 49~64초다.
- 전체 기간에서는 간격 중앙 62초, p95 124초, p99 234초다.
- 2분보다 긴 간격은 14,185회, 1시간보다 긴 간격은 7회, 1일보다 긴 간격은 2회다.
- 파일럿 VEL 파형은 326건이며 중앙 간격은 12시간이다.
- 파형은 대체로 UTC 00:00, 12:00에 약 2초 분량을 수집한다. 13시간보다 긴 공백은 4회다.

즉 트렌드는 준연속 저주기 수집이고, 파형은 12시간마다 수집하는 고속 스냅샷이다.

**의견**

osESD 시간 벡터에는 행 번호가 아니라 첫 관측 이후 실제 경과 초를 사용한다. 1시간 이상 공백에서는 detector 상태를 이어가기보다 시계열을 분할하거나 재초기화하는 방식을 비교해야 한다.

#### Q4. 전체 기간과 시계열 길이, 결측·센서 교체·재교정 이력은 무엇인가?

**사실**

- 파일럿 VEL 트렌드: 2026-04-27 10:50:04 ~ 2026-10-29 18:02:10
- 총 118,805건, timestamp 중복 없음, null/0 없음
- 가장 긴 공백: 2026-07-16 09:43:12 ~ 2026-10-06 21:19:16, 약 82.5일
- 그 밖에 약 33.8시간, 11.8시간, 7.4시간 공백이 있다.
- VEL 파형: 2026-04-27 ~ 2026-10-29, 326건
- 일반 센서 교체·재교정 이력을 직접 기록한 테이블은 확인되지 않았다. setpoint의 갱신 시각은 있지만 교정 이력으로 해석할 수 없다.

**의견**

118,805건을 하나의 연속 스트림으로 취급하면 안 된다. 최소한 82.5일 공백 전후를 다른 run으로 나눈다. 초기 Phase 2는 2026-10-06 이후의 연속 구간을 사용하고, 첫 1~7일을 정상 초기화 후보로 검토한다. 그 구간에 실제 이상이 포함됐는지는 아래의 14.4097 spike를 현장 확인한 뒤 결정한다.

### 11.2 특징과 분석 단위

#### Q5. 현재 사용할 수 있는 특징은 무엇이며 원신호에서 계산해도 되는가?

**사실**

- 파일럿에서 이미 시계열로 저장되는 값: velocity RMS, acceleration RMS, envelope peak-to-peak
- 다른 SYS01/SYS04 setpoint에는 `Direct`, `Direct rms`, `PK`, `1X`, `2X`, BPFO/BPFI/BSF, 대역값 등 계산 채널도 존재한다. 모든 설비에 공통인 것은 아니다.
- 현재 `spectrum_builder.py`는 원시 파형에서 RMS, absolute peak, crest factor, kurtosis, impulse count/regularity, FFT amplitude를 계산할 수 있다.
- 파일럿 파형은 sampling period와 RPM이 비어 있어 주파수·order 관련 특징의 신뢰성에 제한이 있다.

**의견**

원신호에서 특징을 직접 계산하는 것은 가능하다. 다만 Phase 2 기준선은 DB에 이미 저장된 VEL/ACC/ENV3 세 시계열로 만들고, 파형 특징은 검출된 시점의 설명 또는 후속 ablation으로 추가한다. fallback sampling period로 만든 주파수 특징은 반드시 `inferred`로 표시한다.

#### Q6. 센서·축·특징별 시계열인가, 합친 지표인가?

**사실**

DB에는 각 `(회사, 시스템, 포트, point, measurement, 집계 코드, VAL_TYPE)`가 별도 단변량 시계열로 저장된다. 합성 건강지수는 기본 데이터에 없다.

**의견**

센서 위치와 특징별로 osESD를 따로 실행하고 결과를 나중에 합치는 방식이 적합하다. 첫 단계에서 VEL, ACC, ENV3를 하나의 숫자로 합치면 단위와 이상 의미가 사라진다. 결합이 필요하면 `동일 시간창에서 2개 이상 채널 검출` 같은 간단한 late fusion부터 시험한다.

#### Q7. 점 사이 간격과 dwin·rwin·초기 윈도우의 시간 의미는 무엇인가?

**사실**

파일럿 최근 구간은 약 61초/점이다. 따라서 현재 기본값을 그대로 쓰면 대략 다음 시간 범위가 된다.

- `dwin=5`: 약 5분
- `rwin=5`: 약 5분
- `size=100`: 약 100분의 초기화 구간

SYS01 대표 채널은 약 210초/점, SYS04 대표 채널은 약 600초/점이므로 같은 파라미터라도 실제 시간 길이는 약 3.4배, 9.8배가 된다.

**의견**

파라미터를 점 개수가 아니라 목표 시간으로 먼저 정해야 한다. 파일럿에서는 빠른 변화용 5~30분 dwin, 기준 추세용 30분~4시간 rwin을 작은 후보군으로 비교하고, 초기화 구간은 최소 하루 이상을 권장한다. `auto_osESD`의 20% 튜닝 구간에 의심 이벤트가 들어가는지 먼저 표시한 뒤 자동 튜닝 여부를 결정한다.

### 11.3 운전 조건과 라벨

#### Q8. 속도·부하·온도와 기동·정지 조건은 기록되어 있는가?

**사실**

- 파일럿 설비의 `TB_EQUIP_INFO` 행이 없어 설계/실측 RPM과 정격 정보가 없다.
- 파일럿 SKF waveform의 RPM도 null이다.
- 파일럿 setpoint에는 VEL, ACC, ENV3만 있으며 부하·온도 채널은 없다.
- 최근 VEL 5,000건에는 0이 없지만 이것만으로 계속 운전 중이었다고 확정할 수 없다.

**의견**

현재 데이터만으로 운전 조건 보정은 불가능하다. Phase 2 결과에서 장기 level shift를 곧바로 고장으로 부르지 말고 `운전 조건 변화 또는 이상 후보`로 남긴다. 기동·정지 플래그가 확보되기 전에는 낮은 진동 구간과 급격한 level change를 별도 분석하고, 현장 운전 로그가 있으면 이후 결합한다.

#### Q9. 알려진 고장·정비·부품 교체 이력이 있는가?

**사실**

- 플랫폼 전체 `TB_MAINTENANCE_ACTION`은 약 10건, `TB_EVENT_REPLY`는 약 78건으로 매우 적다.
- 파일럿 설비에는 연결되는 maintenance action, equipment info, alarm event가 없다.
- 파일럿 VEL 전체 기간의 최대값은 14.4097 mm/s rms이며 2026-10-12 11:33:00에 한 번 나타났다.
- 2026-05-08에는 4.5 mm/s rms가 5회 연속 기록됐다.
- 현재 setpoint는 Warning 3.3, Danger 4.4 mm/s rms지만 이 임계값이 과거 전 기간에 동일했는지는 알 수 없다.

**의견**

14.4097 spike와 4.5 plateau는 좋은 검토 대상이지만, 현장 확인 전에는 고장 라벨이 아니다. 전자는 단발 센서 spike일 수 있고 후자는 clipping, 시험 입력 또는 실제 고진동일 수 있다. 지도교수/현장 담당자에게 이 두 구간의 운전·정비 기록을 우선 확인하는 것이 효율적이다.

#### Q10. 기존 경보 기준과 경보 빈도는 무엇인가?

**사실**

- 파일럿 VEL 채널의 현재 고정 임계값은 Warning 3.3, Danger 4.4 mm/s rms다.
- 파일럿 설비 키로 직접 연결되는 알람은 조회되지 않았다.
- 플랫폼 전체 2026년 10월 알람은 SYS01 589건, SYS04 705건, SKF 540건이다.
- ISO 20816 계산 코드와 custom setpoint가 있지만 파일럿 채널의 운영 알람이 ISO 기준으로 생성됐다고 확인되지는 않았다.

**의견**

osESD는 기존 임계값을 대체하는 것이 아니라 변화 기반 조기경보를 보완하는 방식으로 평가하는 것이 안전하다. `고정 임계값 미만에서 osESD가 먼저 검출했는가`, `임계값 알람 이후 반복 오탐을 얼마나 만들었는가`를 비교한다.

#### Q11. 기록된 이상이 없을 때 어떤 평가가 적합한가?

**사실**

현재 파일럿에는 확정 고장 라벨이 없다. 알람과 AI 진단 결과는 존재하지만 독립적인 정비 확인 정답은 부족하다.

**의견**

제안된 세 평가를 모두 사용하되 역할을 분리한다.

1. 파일럿 SKF 연속 구간: 정상 가정 하의 일/주당 오탐 수, 연쇄 검출 길이, 공백 직후 오탐을 평가
2. 같은 신호에 spike, level shift, drift, variance change를 주입: 유형별 재현율과 검출 지연을 평가
3. 알람 또는 정비 이력이 있는 별도 설비 1대: 실제 사건 전후 case study를 수행

수업·논문 평가에는 이 세 축이 가장 방어 가능하다. 합성 이상만으로 실제 고장 탐지 성능을 주장하지 않고, 정상 오탐·통제된 재현율·실제 사례를 각각 별도 표로 제시한다.

### 11.4 최종 Phase 2 범위 제안

1차 데이터셋은 다음처럼 고정한다.

```text
설비: KKPC Ulsan / G2 / R-3 POLYM PUMP / MOTOR
시스템: SYS1_ID=99, COMPANY_ID=3, API_PORT=8082
주 채널: POINT_ID=105, MEASUREMENT_ID=107, MTR_H_DE_VEL, mm/s rms

```
